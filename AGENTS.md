Read this file, then [`docs/DEVELOPER-GUIDE.md`](docs/DEVELOPER-GUIDE.md) for the area you are changing.

**This file is documentation.** [`CONSTITUTION.md`](CONSTITUTION.md) is policy and outranks this file. [`CONTRIBUTING.md`](CONTRIBUTING.md) is how a pull request is made. If this file conflicts with the constitution, the constitution wins and this file should be fixed.

## What this repository is

Two Tk desktop programs for loading ATAK phones with maps:

- **ATAK Device Installer** — `scripts/atak_adb_deploy.py`. On completion the user exits and runs the downloader. The installer does not launch it.
- **ATAK Imagery Downloader** — `scripts/atak_downloader_finalbuild.py`. `scripts/atak_downloader_from_installer.py` is the follow-on entry that skips the USB intro.

Linux code in `scripts/` is the source of truth. Windows files `windows_build/*_win.py` are generated by `scripts/sync_windows_build.py`. GitHub: `atakmaps/atak-imagery`. Current version is the `VERSION` file.

ATAK 5.6+ only. UV-PRO and MeshCore plugins are installed from their own GitHub releases. Their source is not in this repo.

`README.md` is the user install guide. Handoff markdown in the repo root is session history.

## Before you edit

1. Read the constitution.
2. Change behavior in `scripts/`, not in a `*_win.py` copy.
3. Do not merge the Device Installer into the standalone downloader, and do not make the installer auto-launch imagery. UV-PRO and MeshCore stay two installer choices (`TAK-UV-PRO` and `TAK-MESHCORE` GitHub releases), even though the UV-PRO plugin APK also speaks MeshCore.
4. Do not bump `VERSION`, rewrite `deploy.env.example` release tags, or publish a GitHub release unless the maintainer asked for a release.
5. Do not commit `deploy.env`, tokens, tile trees, DTED, SQLite, or `.venv`.
6. Do not add Windows-only APIs to Linux sources. Sync refuses those markers.

## Run

Linux, from a clone:

```bash
chmod +x install_linux.sh
./install_linux.sh
```

Then use the **ATAK Device Installer** or **ATAK Imagery Downloader** launcher. For a code change, the venv interpreter is `.venv/bin/python` after install. A direct run from `scripts/` only works once that environment exists:

```bash
.venv/bin/python scripts/atak_downloader_finalbuild.py
.venv/bin/python scripts/atak_adb_deploy.py
```

There is no unit-test suite that covers the wizards. Say what you ran.

After a Linux behavior change that Windows must match:

```bash
python3 scripts/sync_windows_build.py
python3 scripts/audit_windows_bundle.py
```

Building the EXEs happens on Windows. Do not claim Windows was built if you only ran sync on Linux.

## Pull requests

Branch from current `main`. `main` is protected. Open a pull request. Do not merge it and do not force-push `main`. The maintainer reviews.

Say what changed, whether you exercised Device Installer, Imagery Downloader, or both, and whether `VERSION` or release assets were touched.

## Linux release notes

When the maintainer asks for a Linux release, notes describe `atak-imagery-vX.Y.Z-linux-install.zip`, `install_linux.sh`, and the two launcher names. They do not include Windows steps unless the maintainer asked to publish Windows too. Build the zip with `python3 scripts/build_release.py`. The user zip does not contain this guide.
